# 세션 인수인계 규칙 (Session Handoff Rules)

여러 세션이 같은 프로젝트에서 **동시에** 돌아도 충돌하지 않고, **컨텍스트 압축(compact)** 이 일어나도 맥락을 잃지 않게 하는 규칙. 이 플러그인의 훅과 `/handoff` 명령이 아래 규칙을 자동으로 상기·집행한다.

## 1. 파일 구조 (충돌 방지의 핵심)

- 프로젝트 루트에 `.handoff/` 디렉터리를 둔다. 없으면 만든다.
- **각 세션은 자기만의 파일 하나만** 쓴다: `.handoff/<세션식별자>.md`
  - 그 세션이 사는 동안 **그 파일 하나만** 갱신한다. 다른 세션 파일은 **읽기(겹침 확인) 외에는 건드리지 않는다**.
  - **날짜·시각을 파일명에 넣지 않는다.** 시각은 파일 내부 "최종 갱신 시각" 필드로만 관리한다.
- 통합 뷰로 `.handoff/INDEX.md`를 둔다. 각 세션의 **한 줄 요약**만 담는다: `세션식별자 | 최종 갱신 시각 | 상태(진행중/완료/중단) | 주제`. **자기 줄만** 갱신한다.

### 1-1. 세션식별자 규칙

세션식별자는 `.handoff/<세션식별자>.md`의 파일명이자 동시성 충돌을 막는 키다. 슬러그가 겹치면 두 세션이 같은 파일을 덮어써 규칙이 깨지므로:

- **형식**: 소문자 영숫자 + 하이픈만(`[a-z0-9-]`). 공백·한글·특수문자 금지(파일명·git 안전). 대략 40자 이내.
- **구성**: `<주제슬러그>-<세션토큰>`
  - 주제슬러그: 작업 주제 기반 1~4단어(예: `kmc-svr-migration`, `traffic-analysis`).
  - 세션토큰: **세션 시작 훅이 주입하는 6자리 고유 토큰**(세션 UUID 기반). 접미사로 붙이면 동시 세션끼리 파일명이 **절대** 겹치지 않는다. 예: `traffic-analysis-ba2968`.
- **유일성**: 훅 토큰을 접미사로 반드시 붙인다. 토큰이 없으면 INDEX의 기존 식별자와 겹치지 않게 짓고, 겹치면 `-2`/`-b` 등으로 구분한다. **다른 세션이 INDEX에 올린 식별자는 재사용 금지.**
- **한 세션 = 한 식별자(불변)**: 시작 시 한 번 정하고 끝까지 유지. 주제가 바뀌어도 파일 안에서 섹션으로 구분(새 파일 X).
- **압축·재개 후**: 세션토큰은 그대로이므로 새 파일을 만들지 말고, 토큰으로 `.handoff/*-<토큰>.md`를 찾아 **같은 파일을 재-채택**한다.

## 2. 동시성 원칙 (왜 충돌하지 않는가)

- 한 세션은 오직 **자기 파일 + INDEX.md의 자기 줄**만 쓴다. 이 "파일 단위 소유권"이 동시 실행 충돌을 원천 차단한다.
- 시작 시 `INDEX.md`(한 줄 요약 모음)만 먼저 읽으므로, 세션이 수십 개 쌓여도 토큰이 절약된다.
- 오래된 "완료" 세션 파일이 쌓이면, 사용자가 원할 때 `.handoff/archive/`로 아카이브하거나 병합 정리를 **제안**한다(임의로 지우지 않음).

## 3. 세션 시작 시

1. 먼저 `.handoff/INDEX.md`**만** 읽어 현황 파악(없으면 `.handoff/`+INDEX 생성).
2. "진행중"/"중단" 세션 중 **내 작업과 겹칠 만한 것**이 있으면 그 파일만 열어 확인하고, 겹치면 사용자에게 알린다.
3. 이번 세션 전용 파일(`.handoff/<내-식별자>.md`)을 만들고 INDEX에 자기 줄을 추가한다.

## 4. 갱신 시점

- (a) 사용자가 "핸드오프 갱신"/`/handoff` 요청 시
- (b) **컨텍스트 압축이 임박**했다고 판단될 때(압축 전 내보내기)
- (c) 의미 있는 작업 단위 **완료** 시
- (d) **세션 종료 신호**가 보일 때

갱신 시 **자기 세션 파일 + INDEX의 자기 줄만** 갱신한다. 끝나면 `handoff 갱신 완료 (<세션식별자>)` 라고만 알린다.

## 5. 세션 파일 형식

다음 세션의 내가 **이 파일 하나만 읽고 이어갈 수 있게** 쓴다. 코드를 통째로 복사하지 말고 "**어디에 무엇이 있고 왜 그런지**"를 남긴다.

```markdown
# Handoff: <세션식별자>

- **최종 갱신 시각**: YYYY-MM-DD HH:MM (KST)
- **상태**: 진행중 / 완료 / 중단

## 프로젝트 개요
## 현재 상태        (결과 위주 + 파일 경로:라인)
## 다음에 할 일
## 중요 결정·맥락    (왜 이렇게 했는지, 버린 방향)
## 미해결 이슈
```

## 6. 압축(compact) 대응

컨텍스트 압축은 세션 **도중**에 일어나며 세부가 요약본으로 사라질 수 있다. 압축은 "기억을 잃는 순간"으로 간주한다.

- **압축 전**: 임박했다고 판단되면 자기 세션 파일과 INDEX를 먼저 최신화(기억을 파일로 내보냄).
- **압축 후 복원**: 압축 정황이 감지되거나 훅이 복원 리마인더를 주입하면, **즉시 `.handoff/INDEX.md`와 내 세션 파일을 다시 읽어** 복원한다.
- **원본에서 세부 복구**: 요약본에서 세부가 사라졌으면 세션 폴더의 `archive/compact-<시각>.jsonl`(압축 직전 대화 원본, 훅이 자동 저장)에서 복구한다 — 원본을 직접 읽지 말고 **`/restore`** 를 쓴다.
- **소유권 유지**: 압축 후에도 세션 파일명(`.handoff/<식별자>.md`)을 작업 중 반복 명시한다.

> 이 규칙들은 플러그인의 훅(`hooks/hooks.json`)과 `scripts/handoff_hook.mjs`가 자동 집행한다.
> 세부 동작은 [README.md](./README.md) 참조.
